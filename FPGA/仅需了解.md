# Rust 嵌入式学习笔记：FPGA 只需了解的三件事

学习目标：不写 FPGA 逻辑、不买开发板。学完能回答三个问题：**FPGA 和 MCU 有什么区别？什么时候才需要 FPGA？Rust 怎么和 FPGA 分工？**

## 1. FPGA 和 MCU 的区别：配置外设，还是定制外设

你熟悉的 STM32 是一个很好的参照：

| 对比 | STM32 MCU | FPGA |
|---|---|---|
| 你在改变什么？ | 写 Rust 固件，让 CPU 执行程序；通过寄存器配置现成外设 | 配置芯片内部的逻辑单元和连线，让它们组成所需的数字电路 |
| 用编码器举例 | 把支持编码器模式的定时器配置好，定时器就能根据 A/B 信号自动加减计数 | 可以设计自己的编码器计数模块，决定通道数、计数规则，以及何时锁存所有通道的结果 |

关键不是“MCU 串行、FPGA 并行”。STM32 的定时器也能在 CPU 执行其他任务时独立计数，CPU 不需要处理每一次电平变化。真正的区别在于：**MCU 的外设功能由芯片厂商设计好，你选模式；FPGA 的可编程逻辑允许你自己定义外设功能。** 例如，FPGA 里的查找表（LUT）可实现组合逻辑，触发器可在时钟边沿保存状态；知道这两者分别负责“算”和“记”就够了。 [st](https://www.st.com/resource/en/product_training/STM32G4-WDG_TIMERS-General_Purpose_Timer_GPTIM.pdf)

## 2. 什么时候考虑 FPGA：先找出 MCU 到底哪里不够

还是用机器人编码器举例：

- 只接两路编码器，而所选 STM32 恰好有两个可用的编码器定时器，引脚和输入速率也满足要求：先用 STM32。定时器负责数脉冲，Rust 只需要在控制周期里读取计数，不必给每个脉冲写中断处理。 [st](https://www.st.com/resource/en/product_training/STM32G4-WDG_TIMERS-General_Purpose_Timer_GPTIM.pdf)
- 要接八路编码器，还要求同一触发沿保存八路计数：先查 MCU 的定时器数量、引脚复用，以及硬件触发能否满足要求。如果现有外设做不到，再比较换 MCU、加专用计数芯片，还是用 FPGA 做多路并行计数与统一锁存。 [st](https://www.st.com/resource/en/product_training/STM32G4-WDG_TIMERS-General_Purpose_Timer_GPTIM.pdf)

这里有个容易混淆的点：**读得快，不等于采得齐。** 假设要求八路计数的采样时间差不超过 1 µs，而 Rust 依次读取八个计数寄存器，第一路和最后一路相差 5 µs，那就不满足要求。你真正需要的是让硬件在同一个触发事件上保存各路计数，之后 Rust 再慢慢读。这个例子里，应先查 MCU 能不能做到硬件同步，而不是一看到“1 µs”就上 FPGA。 [docs.amd](https://docs.amd.com/api/khub/documents/juMnxca71Tf2gfjmNyjM8A/content)

## 3. Rust 怎么和 FPGA 分工：软件管配置和决策，硬件管采集和时序

以 Zynq-7000 为例，一颗芯片里同时有处理系统（PS，含 ARM CPU）和可编程逻辑（PL，FPGA 部分）。Rust 程序可以跑在 ARM 上；PL 里的电路独立工作。你从嵌入式软件视角，只需要认得三种交互方式： [docs.amd](https://docs.amd.com/api/khub/documents/juMnxca71Tf2gfjmNyjM8A/content)

| 方式 | 回答什么问题？ | 编码器例子 |
|---|---|---|
| 寄存器 | 怎么配置？怎么读状态？ | Rust 写入启动配置，读取当前计数或错误标志。 |
| 中断 | 硬件什么时候需要通知 CPU？ | 一批采样完成后，FPGA 发中断，让软件知道可以取数据了。 |
| DMA | 大批数据怎么搬进内存？ | 连续采样时，用 DMA 把数据传到 RAM，不用 CPU 逐条搬运；Rust 再处理缓冲区。 |

这三种方式可以配合使用：**寄存器配置采集 → 硬件采集 → DMA 搬运 → 中断通知**。但如果你只是偶尔读一次位置，直接读寄存器就行，不需要为了“用上 FPGA”把三种都加进去。 [docs.amd](https://docs.amd.com/api/khub/documents/juMnxca71Tf2gfjmNyjM8A/content)
